# 天气网站设计文档

## 1. 项目概述

### 1.1 目标
打造一个具有 Apple Liquid Glass 视觉风格的天气网站，数据来源中国天气网，支持浏览器 GPS 定位，覆盖实时天气、逐小时/逐天预报、雷达/卫星图、专业气象图、生活健康指数和恶劣天气预警。

### 1.2 范围
完整 MVP，一次性实现以下模块：
- 实时天气与基础气象信息
- 逐小时预报（24-72 小时）
- 逐天预报（7-15 天）
- 气象雷达图与卫星云图
- 专业数据可视化（趋势曲线、风向玫瑰图）
- 空气质量指数（AQI）与污染物
- 生活与健康指数
- 恶劣天气预警弹窗
- 浏览器 GPS 定位与手动城市搜索

## 2. 技术栈

### 2.1 前端
- **构建工具**：Vite
- **框架**：React 18
- **语言**：TypeScript
- **样式**：Tailwind CSS
- **动画**：Framer Motion + CSS 动画
- **图表**：Recharts
- **地图**：Leaflet
- **状态管理**：Zustand
- **图标**：Lucide React

### 2.2 后端
- **框架**：Express + TypeScript
- **缓存**：node-cache（内存）
- **HTTP 客户端**：axios
- **HTML 解析**：cheerio
- **动态渲染备选**：puppeteer

### 2.3 共享
- `packages/types`：前后端共享 TypeScript 类型定义

```
┌─────────────┐      REST API      ┌─────────────┐      抓取/解析      ┌─────────────────┐
│  Web 前端   │  ◄──────────────►  │  Express    │  ◄──────────────►  │  中国天气网     │
│  (Vite)     │                    │  后端服务   │                    │                 │
└─────────────┘                    └──────┬──────┘                    └─────────────────┘
                                          │
                                          ▼
                                    ┌─────────────┐
                                    │  node-cache │
                                    │  内存缓存   │
                                    └─────────────┘
```

### 3.1 数据流
1. 浏览器通过 `navigator.geolocation` 获取坐标，失败时回退到 IP 定位，并支持手动城市搜索。
2. 前端调用后端 REST API 获取天气数据。
3. 后端作为中国天气网的代理爬虫，负责抓取、解析、分级缓存。
4. 数据按类型设置不同 TTL，减少源站压力并保证数据新鲜度。

## 4. 前端设计

### 4.1 视觉系统：动态流体 Liquid Glass
- **背景**：全屏缓慢流动的极光/晚霞渐变，使用 CSS `background-size: 400% 400%` 配合 `animation` 实现流动效果。色调根据天气类型动态微调：晴天偏金橙，雨天偏青蓝，夜晚偏紫蓝。
- **玻璃卡片**：`backdrop-filter: blur(24px) saturate(180%)`，半透明白色背景 `rgba(255,255,255,0.08)`，1px 高光边框，柔和阴影。
- **字体**：Inter / SF Pro 风格，大温度使用超细字重（font-thin），辅助信息使用常规字重。
- **圆角**：卡片使用大圆角（20px-28px），按钮和标签使用小圆角（12px-16px）。

### 4.2 页面结构（沉浸式长页面）
1. **Hero 区**：城市名、大温度、天气现象图标、体感温度、更新时间。
2. **逐小时预报**：横向时间轴，展示温度曲线和降雨概率柱状图。
3. **逐天预报**：7-15 天卡片/列表，展示每日最高/最低温度、天气图标、风向风力、降水概率。
4. **当前详情网格**：风力风向、相对湿度、能见度、气压、日出日落。
5. **雷达/卫星图**：Leaflet 地图叠加中国天气网雷达/卫星瓦片，支持播放/暂停时间轴。
6. **专业数据图**：温度/湿度/气压趋势曲线、风向风速玫瑰图。
7. **生活指数**：穿衣、紫外线、洗车、晾晒、感冒、过敏、运动、钓鱼等卡片。
8. **AQI 区**：AQI 数值、主要污染物浓度、健康建议。
9. **恶劣天气预警**：进入页面时中央弹窗展示预警信息，附防御指南。

### 4.3 动画策略
- **页面加载**：玻璃卡片依次上浮淡入，stagger 0.08s。
- **滚动触发**：使用 Framer Motion `whileInView`，模块进入视口时执行缩放 + 模糊淡入。
- **数据更新**：数字滚动动画、温度曲线重绘。
- **背景**：渐变缓慢流动，天气图标微动效。
- **交互**：卡片 hover 时轻微上浮 + 边框高亮。

### 4.4 响应式策略
- **移动端**：单列布局，逐小时横向滚动，地图占满屏幕宽度。
- **平板**：部分卡片双列布局。
- **桌面**：最大内容宽度 1440px，多列网格，地图固定高度。

## 5. 后端设计

### 5.1 后端职责
- 作为中国天气网的唯一代理，避免前端直接跨域请求和反爬。
- 抓取、解析、统一数据结构。
- 按数据类型分级缓存，控制请求频率。

### 5.2 API 设计
| 端点 | 说明 |
|------|------|
| `GET /api/weather/current?lat={}&lon={}` | 实时天气 |
| `GET /api/weather/hourly?lat={}&lon={}` | 逐小时预报 |
| `GET /api/weather/daily?lat={}&lon={}` | 逐天预报 |
| `GET /api/weather/air?lat={}&lon={}` | AQI 与污染物 |
| `GET /api/weather/lifestyle?lat={}&lon={}` | 生活指数 |
| `GET /api/weather/alerts?lat={}&lon={}` | 天气预警 |
| `GET /api/radar/tiles?type=radar\|satellite&time={}` | 雷达/卫星瓦片代理 |
| `GET /api/geocode/reverse?lat={}&lon={}` | 坐标转城市 |

### 5.3 爬虫策略
- 优先解析中国天气网公开页面中的 JSON 数据或 API 端点。
- 使用 axios + cheerio 解析 HTML。
- 设置合理的 User-Agent、Referer，控制并发。
- 若页面为动态渲染，使用 puppeteer 作为备选方案。
- 反爬防护：请求间隔、缓存、失败重试 3 次。

### 5.4 缓存策略
使用 node-cache 内存缓存，TTL 如下：

| 数据类型 | TTL |
|----------|-----|
| 实时天气 | 5 分钟 |
| 逐小时预报 | 30 分钟 |
| 逐天预报 | 1 小时 |
| AQI | 15 分钟 |
| 生活指数 | 1 小时 |
| 预警 | 5 分钟 |
| 雷达/卫星瓦片列表 | 10 分钟 |

### 5.5 错误处理
- 爬虫失败时返回缓存数据（若存在）。
- 无缓存时返回 503 并附带错误信息。
- 前端显示友好占位和手动刷新按钮。
- 定位失败时回退到 IP 定位，再失败则默认展示北京。

## 6. 测试策略

- **前端单元测试**：Vitest + React Testing Library，测试组件渲染和交互。
- **后端单元测试**：Jest + Supertest，测试 API 路由和爬虫解析逻辑。
- **端到端测试**：Playwright，测试核心用户流程（定位 → 加载 → 切换城市 → 查看雷达）。
- **爬虫快照测试**：用中国天气网真实页面做快照测试，结构变化时及时告警。

## 7. 部署建议

- **前端**：构建为静态资源，部署到 Vercel / Netlify / Nginx。
- **后端**：部署到 VPS / Railway / Render / Docker。
- **环境变量**：
  - `WEATHER_BASE_URL`：中国天气网基础 URL
  - `CACHE_TTL_*`：各类数据缓存时间
  - `PORT`：后端端口
  - `CORS_ORIGIN`：前端域名

---

## 8. 安全与合规

- 后端统一处理跨域，前端不直接请求中国天气网。
- 遵守 robots.txt，控制请求频率，避免对源站造成压力。
- 不存储用户位置信息，定位仅在客户端使用。

## 10. 关键决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 项目范围 | 完整 MVP | 用户明确要求一次性实现所有模块 |
| 架构 | 独立前端 + Node 后端 | 前后端职责清晰，便于独立部署 |
| 定位方式 | 浏览器 GPS 优先 | 精度最高，失败时回退 IP 定位 |
| 视觉方向 | 动态流体 Liquid Glass | 华丽动画，视觉冲击力强 |
| 首页布局 | 沉浸式长页面 | 强调滚动动画和视觉沉浸感 |
| 地图方案 | Leaflet + 天气网瓦片 | 开源免费，直接利用中国天气网瓦片 |
| 刷新策略 | 按类型分级 | 不同数据更新频率差异大 |
| 预警提醒 | 中央弹窗遮罩 | 确保用户不会错过重要预警 |
| 设备适配 | 全响应式同等重视 | 桌面、平板、手机都要精致 |
| 数据缓存 | 内存缓存 + 频率限制 | 平衡性能与反爬需求 |
| 实现路径 | 现代独立栈 | 开发体验好，完全可控 |
